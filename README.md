# 数据要素治理

当前版本：V31.0

“数据要素治理”是一个面向数据要素主题的研究与公众号内容生产网站：检索新闻 / 政策 / 论文，管理用户引用与上传材料，调用 DeepSeek 生成文章，自动检索并插入配图，再导出 Word / PDF。






## V31.0：生成链路解耦 + 524 超时修复

V31 针对 V30 引入混合视觉后出现的“文章生成请求 524 / 图像系统影响写作主链”做结构性整改。核心原则是：**先把文章稳定生成并交给用户，再在后台独立完成视觉规划与配图**。

- `/api/generate` 现在只负责快速创建后台生成任务并立即返回 `202`；浏览器通过 `/api/generation/<jobId>` 轮询结果，不再让一次 HTTP 长连接等待完整 DeepSeek 写作，因此反向代理的 100 秒级超时不会再把仍在运行的稿件误判成失败。
- DeepSeek 首稿不再承担 `visualType / visualPlan / 代码绘图 DSL` 等视觉策划字段。写作 Prompt 只关心正文、标题、来源关系和事实边界；配图位置、源新闻回图、Serper 找图与代码绘图全部在文章完成后由本地视觉路由判断。
- `writingSpec` 与 `visualSpec` 分开，长度修复和编辑修复不会再携带无关的图片策略参数。
- 图片后台任务延迟约 0.8 秒启动，让正文结果先完成持久化与前端交付，避免小规格服务器上本地 PNG 渲染与首个响应争抢 CPU。
- 即使不再让 LLM 输出 `sourceId` 配图绑定，系统也会从正文 `[n]` 引用标记、来源标题、摘要与 `sourceNotes` 本地恢复源新闻绑定；“。[2]”这类句尾引用也会保留在配图锚点中。
- `compose.html` 对本次 CSS/JS 加版本参数，避免部署后浏览器继续使用 V30 缓存脚本与 V31 API 合同不一致。

本地完整测试：`127 passed`（打包前会再次从最终 ZIP 解压复测）。详见 `docs/V31_RELEASE_NOTES.md`。

## V30.0：智能混合配图 + 本地代码视觉引擎

V30 保留 V29 已经稳定的真实图片回源、Serper 检索、二维码/Logo/无关图过滤，同时新增**不依赖任何图片生成 API**的本地代码视觉引擎。默认不再把“找图”和“画图”当成二选一：具体新闻/案例先找源图和真实网络图；流程、机制、因果、对比、分层、时间线、指标等结构化段落可以直接画；真实图找不到或不够相关时再用代码解释图兜底。

生成页提供五种策略：智能混合（默认）、真实图片优先、解释图优先、全部代码绘图、仅真实图片。选择“全部代码绘图”时正文 **0 次 Serper Images**，因此没有 `SERPER_API_KEY` 也能稳定生成完整图文稿；选择“仅真实图片”时仍维持宁缺毋滥，不用代码图补位。

本地 Renderer 在 `app/code_visuals.py`，支持多样封面以及流程、因果、对比、分层、生态网络、时间线、KPI、矩阵和编辑型概念图。DeepSeek 不生成/执行 Python，只在原文章 JSON 中给出经过白名单清洗的轻量视觉意图；像素全部由可信本地代码生成。没有真实数字时不会为了 KPI 版式编造数字。

质量守恒基准仍保持 Tavily 主链 5 次、Serper 检索兜底最多 3 次、来源页有图时 0 次初始图片搜索；新增代码视觉后没有增加 DeepSeek API 调用。完整离线测试：`119 passed`。

详细说明见 `docs/V30_RELEASE_NOTES.md` 与 `docs/V30_QUALITY_BENCHMARK.md`。

## V29.0：二维码硬拦截与段落级图片精准匹配

V29 针对真实运行中出现的“来源页二维码被当成正文配图”和“只沾到数据治理大主题、却与当前段落无关的泛 AI 图片”做专项修复，保持检索/写作调用预算不变：

- 图片下载后增加**像素级二维码识别**：不依赖文件名、URL、OCR 或外部模型，通过 QR finder pattern 与高对比模块特征识别大尺寸二维码/关注卡；即使 CDN 文件名是随机哈希也会被拒绝。
- 来源页 HTML 层增加“二维码 / 扫码 / 公众号 / 微信”等 alt、class、URL 文本硬过滤，二维码在进入图片候选池前即可被提前清理。
- 发布机构**首页不再视为具体新闻/案例原文页**。根域主页的 `og:image`、首页二维码、站点推广图不会获得“源新闻原图”加权；仍保留域名/标题用于 Google Images 定向搜索。
- 正文图片增加段落级业务场景路由：仓库/库存/入库、供应链/物流、制造/生产线、销售/订单、财务、医疗、交通等会生成对应的短图片 Query，而不是统一退化为“数据治理 + AI + 科技”。
- Serper 候选若当前段落已经出现明确业务场景，必须命中该局部场景或同义路线；只重复“数据治理/人工智能”大词的图片不能再靠全局主题得分混入正文。
- 源新闻/案例原图仍保留优先级；但“原图优先”不再覆盖二维码、Logo、关注卡等视觉卫生门禁。
- 正常路径 API 预算不增加：质量基准仍为 Tavily 主链 5 次、Serper 搜索兜底最多 3 次、无来源正文图首轮 1 次、有可用来源原图时 0 次。

新增 7 个 V29 图片精度回归用例，完整离线测试现为 `107 passed`。固定业务场景样例中，“AI 汽车识别”候选从可通过改为直接拒绝，而“仓库/库存/入库”图片正常通过；图片 Query 首选变为 `仓库 库存管理 入库 数据采集`。

详细说明见 `docs/V29_RELEASE_NOTES.md` 与 `docs/V29_IMAGE_PRECISION_AUDIT.md`。

## V10 最重要的改动

### 1. AI 写作不再有“假生成”

旧版本如果 DeepSeek 未配置或请求失败，曾会静默退回本地模板。这会造成两个严重问题：API 没有 Token 消耗，但页面看起来像生成成功；用户选的字数、风格和结构也无法真正生效。

当前版本保持这条硬规则：

- `DEEPSEEK_API_KEY` 未配置：生成按钮直接显示未连接并禁用。
- DeepSeek 请求失败：接口返回明确错误，不再伪装成 AI 结果。
- 生成成功后，“生成分析”会显示真实 API 调用次数、模型、输入 Token、输出 Token、推理 Token、总 Token。
- 服务端同时记录每个阶段：`draft`、`editorial`、`length-repair-*`、`revision`。

默认模型：`deepseek-v4-flash`。

### 2. “字数 / 风格 / 读者 / 结构”等控件全部进入真实生成链路

生成页目前支持：

- 文章类型：行业观察 / 政策解读 / 学术科普 / 热点评论 / 研究简报 / 趋势分析 / 案例拆解。
- 目标读者：产业政策关注者 / 企业管理者 / 数据从业者 / 研究人员 / 高校学生 / 普通公众。
- 篇幅：1000-1400 / 1800-2400 / 2800-3600 / 4000 字左右。
- 语言语气、标题偏好、文章结构、开头方式、段落节奏、证据表达、结尾方式。
- AI 套话抑制、单阶段 / 双阶段主编精修。

这些选项不再只是把选项名塞进 Prompt。`pipeline.py` 会把每一个选项翻译成明确的编辑规则，例如“企业管理者”强调决策影响和风险边界，“学术严谨”要求明确证据强弱，“紧凑短段”要求多数段落 2-4 句等。

篇幅采用后验校验：

1. DeepSeek 首稿。
2. 深度模式执行第二次主编精修。
3. 服务端计算真实正文字符数。
4. 如果未进入用户所选区间，再调用 DeepSeek 做长度校正。
5. 最多自动校正两次，并把最终实际字数和是否达标显示在“生成分析”。

因此不会再为了省 Token 把 2000 字要求写成几百字短稿。

### 3. “自动添加佐证材料”由用户决定

生成页新增开关：`自动添加佐证材料`。

- 开启：当前没有引用 / 上传材料时，系统自动检索新闻、政策、论文，选择真实结果进入证据包。
- 关闭：只使用用户自己从查询页引用的材料和上传文件；如果一条材料都没有，就只按主题和写作要求调用 DeepSeek，不会偷偷插入新闻、论文或演示数据。
- 系统不会生成、注入或展示演示新闻/论文作为真实检索结果；没有真实来源时保持为空。

从查询页带入的新闻 / 论文和用户上传的 PDF / DOCX / TXT 等会显示“已引用”。

### 4. 图片搜索统一改为 Serper / Google Images

V10 不再使用 Brave，也不再让 Tavily 参与文章配图。图片相关链路全部交给 `Serper`：

1. DeepSeek 根据文章主题、章节标题和段落作用给出具体检索词。
2. 后端调用 `https://google.serper.dev/images` 获取 Google Images 结果。
3. 使用原图 URL、Google 缩略图、来源页、标题、来源站点、尺寸和结果位置进行重排。
4. 继续执行语义匹配、logo/icon 过滤、尺寸/比例检查、可下载性检测、URL 去重、感知哈希去重和来源站点去重。
5. 最终图片直接插入正文，并复用到 Word / PDF 导出。

只需配置：

```env
SERPER_API_KEY=你的_key
```

Tavily 仍只负责新闻 / 政策检索与正文资料抽取，Tavily 论文检索 负责论文，DeepSeek 负责写作。

若 `SERPER_API_KEY` 未配置，生成页会明确提示“Serper 图片搜索未配置”，不会把 Tavily 悄悄当图片后备。

### 5. 导出按钮显著化，并增加结构校验

文章右侧增加常驻“导出成品”区域：

- 大号 `导出 Word .docx` 按钮。
- 大号 `导出 PDF` 按钮。
- HTML / Markdown 作为次要导出。

默认排版：

- 标题 / 二级标题：黑体。
- 正文：宋体。
- 正文首行缩进 2 个中文字符。
- 自动选中的图片按网页最终稿位置嵌入 Word / PDF，而不是导出图片 URL。

服务端在把文件发给浏览器前会再次做结构校验：

- DOCX：检查 ZIP 完整性、`word/document.xml`、`word/styles.xml`、正文结构；有配图时确认 `word/media/` 真实存在。
- PDF：检查 `%PDF` / `%%EOF`，再使用 `pypdf` 打开并遍历页面对象。

### 6. 生成后继续修改

文章生成后支持：

- 划选一句话修改。
- 点击段落修改。
- 修改整个二级标题章节。
- 基于当前稿整篇重写。
- 撤回上一次修改。
- 恢复初稿。
- 结构变化时重新匹配图片。

再次修改仍调用 DeepSeek，并默认继承初稿的文章类型、读者、语言语气、结构和篇幅，除非用户本次明确要求改变。


## V18.0 检索理解优化

查询页新增“附加描述”。用户可以用自然语言说明地区、时间、媒体/官方来源偏好、排除项、希望怎样排序等。若填写描述，系统先用 DeepSeek V4 Flash 非思考模式做一次低成本检索意图解析，并缓存结果，再生成国内新闻、国际新闻、政策、论文四类精确搜索句；随后先做用户意图相关性门禁，再做真实来源验证与排序。

结果页会显示“这次我理解你的需求是……”以及每条结果的“为什么匹配”。提供商的 `answer` 不再直接展示，避免搜索引擎摘要偏题。经过验证的页面 `meta description` 会覆盖原始搜索摘要，验证码、限流提示、聚合页和导航页不能进入结果。

首页推荐使用独立的真实主题查询，不复用旧的错误查询缓存；旧版搜索快照和首页缓存均已版本化。

## 图片来源与转载提醒

系统不把图片限制在开放图片集：可以直接检索互联网图片，也可以在文章已引用的新闻/政策来源中优先寻找原报道配图；导出与公众号富文本会保留图片来源名称和来源页。技术上“可检索到”不等于自动获得转载许可，正式发布时仍应依据实际授权、平台规则和合理使用边界决定是否采用。


## 数据真实性原则

本项目不注入演示新闻、演示论文、虚构来源或伪造外链。可读取的原文继续做标题/页面一致性核验；对于政府和媒体站点的反爬页面，如果搜索索引已经明确定位原文、标题高度一致且主题匹配，可标记为“已定位原文”并进入候选。404/410、聚合页、标题错配和明显无关结果仍会剔除。


### 生成与导出
正文配图数量不包含封面；支持自定义正文配图数量和智能分点。Word/PDF 导出提供浏览器原生 GET 下载链路，服务器端在缺少 python-docx/reportlab 时仍有自包含回退方案。
