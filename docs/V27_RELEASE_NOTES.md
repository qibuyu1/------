# V27.0 正文配图召回与匹配专项强化

V26 为了降低 Serper Images 调用，把无源图的初始图片查询从两路收敛为一路，并让已有来源页图片先独占尝试。速度和调用量下降了，但真实使用中暴露出一个回归：部分正文图片位在首条 Query 太窄、来源页前几张图片不可用时会直接落空，出现“要求 3 张，实际只有 1 张”的情况。

V27 的原则是：**恢复图片召回率，但不回到长 Query、串行补搜和无关科技图凑数。**

## 1. 图片 Query 按小节语义生成

旧逻辑会给大量正文位置统一追加“数据分析 科技研发 真实场景 / 数据平台 数据可视化 研发现场”。这对研发文章尚可，但对“为什么数据治理总是失败”“数据治理如何影响普通人”明显偏题。

V27 增加本地视觉语义路线：

- 失败/困境：数据孤岛、数据质量、数据标准、主数据、数据平台；
- 普通人/个人：个人信息保护、隐私、数字生活、数字政务、个人信息权益；
- 企业业务：企业数据治理、业务数据、经营决策、数据平台；
- 研发创新：数据驱动研发、数据平台、实验室、机器学习；
- 安全合规、公共数据、数据资产、可信数据空间、AI/训练数据分别有独立路线。

这些规则完全本地执行，不增加 DeepSeek Token。

## 2. 长自然语言不再直接进入图片搜索

V26 某些图片位虽然名义上“短 Query”，但 `slot.query` 中仍可能包含小标题 + 一整句正文，最终又被拼回 Google Images。V27 改为只提取 2—3 个核心概念，再与当前小节的视觉路线组合；查询通常几十个字符以内。

## 3. 更强的源新闻找图能力

除了 Tavily Extract 已经提供的 `sourceImages`，V27 会在视觉任务中并行读取绑定来源页的：

- `og:image` / `twitter:image`；
- JSON-LD `image / imageUrl / thumbnailUrl`；
- 具有正文/figure/article 特征的大图标签。

这一路直接访问已经引用的源页面，不调用新的搜索 API。候选仍必须经过公共 URL、安全、尺寸、重复、下载可用性和语义门禁。

## 4. 修复“真实来源图在第 5/6 张却永远选不到”

V26 允许来源页前 6 张图片通过语义检查，但首轮只实际探测排序前 4 张 URL，因此第 5/6 张即使是真实正文图也无法被选中。V27 将首轮候选探测扩展到 7 个，并全局并行处理。

## 5. 只对缺图位做第二次搜索，而且并行

- 成功图片位：仍然只需要 1 条 Serper Images Query（有可用来源原图时可以是 0 条）；
- 未命中图片位：最多再用 1 条真正不同的主题路线；
- 已绑定来源但源图不可用：总 Serper 图片 Query 上限为 2 条；
- 多个缺图位的补搜与图片探测在同一并发波次执行，不再一个位置失败后串行等下一个。

因此质量提升主要来自更好的 Query、来源页元图、候选池和并发，而不是无限增加调用。

## 6. 语义门禁放宽“相关表达”，不放宽“无关科技图”

候选图片现在可以用个人信息保护/隐私权益、数据孤岛/数据质量、主数据/元数据等视觉同义概念证明相关性；不再要求标题必须机械出现“数据治理”四个字。

笔记本、显卡、CPU、Intel/AMD、游戏本、壁纸、模板素材、Logo、二维码等干扰项仍保持强过滤。

## 7. 回归测试

新增 5 组专项测试：

1. 数据治理失败与普通人主题生成不同、正确的图片 Query；
2. “个人信息保护 + 隐私权益”可以作为普通人主题的相关图片锚点；
3. 来源页第 6 张真实图片可以在不花 Serper 调用的情况下被选中；
4. Tavily 未返回源图时，来源页 OpenGraph/JSON-LD 元图可以恢复；
5. 三个正文图片位在各自首条主题 Query 有合格候选时可以 3/3 命中。

V27 完整测试：90 passed。
