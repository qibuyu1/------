# V32 Release Notes：全链路二次自查与并发稳定性修复

V32 不是增加新功能，而是针对 V31 的生成、改稿、视觉、证据、导出和前端恢复做一次系统性协调审计。目标是避免“单项功能正常，但组合起来互相覆盖/卡死/丢状态”。

## 关键修复

- 首稿和再次修改都走后台任务；`/api/revise` 不再保留可能触发 524 的长连接。
- 前端会把未完成任务写入 `sessionStorage`，刷新页面后可继续轮询，不再把仍在执行的任务当作丢稿。
- 轮询遇到 502/503/504 或短暂网络错误会重试，而不是第一次波动就宣布生成失败。
- 生成任务队列不再因为容量/TTL 清理正在运行的任务；取消排队任务会尽量停止 Future，运行中任务的结果会被丢弃。
- 文章视觉任务增加 `visualJobToken + contentVersion` 双重版本守卫；旧配图线程只能合并视觉字段，不能拿旧文章快照覆盖已经修改的正文。
- 修改正文时若原视觉仍 `pending/error`，即使用户选择“保留原配图”也会针对新正文重新规划，避免永久卡在 `pending`。
- V31 将 `writingSpec` / `visualSpec` 分离后，改稿路径仍错误从 `writingSpec` 读取图片数量/策略，导致用户设定丢失；V32 已统一从 `visualSpec` 继承。
- 初稿后台配图完成后会同步到“恢复初稿”快照；撤回/恢复会旋转视觉 token，旧线程不会死而复生。
- 保留原配图时不再盲信旧段落索引，而是根据锚点文本和章节做模糊重定位，减少改稿后图片跑到错误段落。
- `[1,2]` / `[1，2]` 组合来源编号现在在正文解析、视觉来源绑定、字数统计和 PDF 富文本中统一处理。
- 长 PDF/DOCX 上传材料不再只保存开头 12k 字符用于后续改稿；会保留文档开头 + 与主题最相关的后部摘录。
- 主题切换时只清除上一主题自动补充的证据，上传文件和手动选择资料不受影响；同主题新一轮自动证据会替换旧自动证据而不是无限累积。
- 导出时前端选择的标题现在真正覆盖 `recommendedTitle`，Word/PDF 不会再悄悄回到模型最初推荐标题。
- PDF/Word 在存在本地代码封面/解释图时会校验媒体对象确实进入成品；外部新闻图片仍按可用性 best-effort，避免因防盗链阻塞整份文档。
- 草稿 TTL 改为“长时间无操作才过期”，而不是从创建时刻硬计时；正在后台配图的草稿在容量淘汰时也会被保护。

## 质量与成本守恒

离线基准保持：Tavily 主链 5 次、Serper 搜索兜底最多 3 次、无来源正文图首轮 Serper Images 1 次、有来源原图时 0 次；结构化代码图仍可 0 次 Serper。首稿 Prompt 不重新引入视觉 DSL。

本版本不新增图片生成 API，也不执行模型生成 Python。

## 最终验收

- 单元 / 回归 / 服务测试：`138 passed`。
- Python 全量编译通过；全部前端 JavaScript 语法检查通过。
- 离线质量基准通过：检索最小正负样本 margin 86；Tavily 主链 5 次；Serper 兜底最多 3 次；无来源正文图首轮 1 次；有来源页原图时 0 次。
- 实际生成含本地代码封面与正文解释图的 DOCX / PDF，并分别渲染为 PNG 逐页检查；未发现中文乱码、图片丢失、裁切、重叠或 Word/PDF 排版分叉。
