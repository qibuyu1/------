# V25.0 发布说明：生成页等高与案例源图匹配优化

V25 在 V24 已解决“长 Query 召回”和“来源页原图抽取”的基础上，继续处理两个细节：生成页右侧文章预览区域过短、页面下方留出大块空白；以及正文图片已经能找到，但对具体案例/新闻来源的绑定还不够稳定。

## 1. 生成页左右栏等高

桌面端不再给文章预览使用固定视口高度。`compose.js` 通过 `ResizeObserver` 监听左侧设置栏真实高度，并把它同步为右侧文章区的高度；文章过长时只在右侧预览内部滚动。这样页面整体长度以左侧设置栏为准，不会在右侧文档下面出现明显空白。

900px 以下的窄屏仍使用自然文档流，避免移动端出现固定高度滚动区。

## 2. 具体案例优先绑定对应来源

写作模型现在可以在 `imageSlots` 中返回 `sourceId`。当某一节写的是具体新闻、政策、机构活动或企业案例时，模型会把图片位绑定到支撑这段内容的来源编号。

配图阶段收到 `sourceId` 后不再只靠标题相似度猜来源，而是直接优先使用该来源的：

- Tavily Extract 同批提取的来源页原图；
- 原报道标题 + 媒体/机构名的 Google Images / Serper 查询；
- 原报道标题 + `site:来源域名` 的定向图片查询。

只有上述路线没有可靠图片时，才退回“文章主题 + 当前段落”的数据科技场景搜索。

## 3. 图片 Query 缩短

V24 的正文图片 Query 在少数场景仍会把主题、模型图片词、小标题和长段落拼得过长。V25 把图片查询压缩为 2—3 个核心短语，单条最多约 180 字符；源新闻标题查询与通用数据科技查询分开执行。

这样既减少“越写得具体越搜不到”的情况，也降低 Google Images 解析长句带来的等待时间。

## 4. 显示未命中的图片位

“配图与来源”面板现在会保留没有命中可靠图片的正文图片位，并显示“未命中可靠图片”，而不是只显示封面后让用户猜是哪几个位置失败。若图片位绑定了来源编号，也会在面板中显示“优先绑定来源 [n]”。

## 5. 来源页图片覆盖

生成前最多采用 6 条证据，V25 会对这 6 条可访问网页统一进行来源页抽取，而不是只抽前 5 条，减少第 6 条恰好是文章核心案例但没有进入源图池的情况。

## 6. 回归测试

新增 V25 回归测试覆盖：

- 右侧文章区跟随左侧设置栏高度；
- `imageSlots.sourceId` 能保留并绑定指定来源；
- 绑定的真实案例源图即使图片标题没有逐字写“数据”，也能凭来源关系进入候选；
- 无来源关系的泛科技图片仍不能绕过数据语义门禁；
- 图片查询保持短 Query，并优先走原报道标题 / 来源站点；
- 正文图片未命中时仍会出现在“配图与来源”审计面板。
