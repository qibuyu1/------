# V28 二次自查记录

## 为什么再查一次

V27 解决了“三张正文图只出一张”的主要召回问题，但进一步按 6—8 张图片、无 Serper、现代新闻页、同域多文章、中文时间和复杂数据术语做边界测试后，仍发现若干平时不容易暴露的问题。V28 将这些问题固化成自动回归测试。

## 本轮发现的真实隐藏 bug

| 风险 | V27 行为 | V28 行为 | 成本变化 |
|---|---|---|---|
| 无 Serper + 有来源 URL | 可能提前结束正文配图 | 仍读取来源页元数据图 | 搜索 API 0 增量 |
| 6—8 个图片位 | 前排可能耗尽 32/36 个探测 URL | round-robin 保证后排也有候选 | 全局上限不变 |
| `srcset` 新闻站 | 可能只看到占位 `src` | 选最大 srcset 候选 | 0 API 增量 |
| 同一媒体域名不同文章 | 可能误享“源新闻”强匹配 | 必须同页或标题强匹配 | 更严格 |
| `AI` 关键词 | 可能命中 detail/main 等字符串 | 拉丁短词按 token 匹配 | 更严格 |
| 8 张正文图 | 后 3 个 model slot 被 sanitize 丢弃 | 完整保留 8 个 | 0 Token 增量 |
| 图片位数量规划 | 4 个候选段落 + 要 3 张时，round() 可能只规划出 2 个位置 | 整数分位保证生成 `min(候选数,要求数)` 个不同位置 | 0 API 增量 |
| 自动图片落点 | 同一小节多个自动图可能都被 heading 分支提前吃掉 | 模型指定图仍按标题；自动补位图按目标段落分散插入 | 0 API 增量 |
| 中文相对日期 | 新鲜度可能未知 | 本地标准化 | 0 API 增量 |
| 数据中心 / 数据中台 | 单字“中”可能误判/拆词 | 语法检测与概念切分分离 | 查询更准 |
| 质量脚本 | 直接运行可能找不到 `app` | 自动加入项目根目录 | 可复现 |

## 不退步约束

`python scripts/quality_benchmark.py` 当前结果：

- 搜索语义正负样本最小 margin：86。
- Tavily 主检索调用：5。
- Serper 网页/新闻兜底：最多 3。
- 无来源图片位首轮 Serper Images：1。
- 有来源页图片时首轮 Serper Images：0。
- 首稿 Prompt 代理总长度：13,318 chars。

因此本轮修复没有通过“多发请求”或“多塞 Prompt”来换质量。
