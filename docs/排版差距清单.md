# 排版/导出链路差距审计（《排版差距清单》）

> 审计对象：`app/exporter.py`（DOCX/PDF 导出）、`app/content_blocks.py`（块结构）、`app/pipeline.py`（`_attach_sources`/`_visual_caption`/`_naturalize_default_structure`）。
> 参考基准：`数治周报.docx`（真实排版样式）。
> 对比物：`数据正在变成石油？….docx`（当前导出产物）。
> 审计方式：用 `zipfile`+`ElementTree` 抽取两份 docx 的 `word/document.xml` / `word/styles.xml`，逐段比对 `pStyle/rPr/pPr` 与直接格式化值。

## 1. 当前 exporter 排版实现清单

**样式配置（`build_docx` L126–144）**
- Normal：宋体/SimSun，`sz=22`（11pt），色 `#1C1C1C`，`line=403 auto`（≈1.68 倍），`after=150`（7.5pt），widowControl 开。
- Title：黑体/SimHei，`sz=49`（24.5pt），色 `#121212`。
- H1/H2/H3：黑体，`sz=33/31/27`（16.5/15.5/13.5pt），色 `#121212`，keepNext。
- Caption 样式默认色 `#4F81BD`，但实际被 run 级覆盖为 `#8198AA`。

**成文流程（`build_docx` L146–218）**
- 标题：`add_paragraph("Title")` 左对齐 + bold 黑体（L147–153）。
- 摘要 deck：普通段 10.5pt、色 `#60778A`，加下边框（L155–162）。
- 封面图：`_docx_add_image` 最大 6.55×4.25in（L164–166）。
- 小标题：`style_name = "Heading 2" if level>=2 else "Heading 1"`（L171–173）→ markdown 的 `##`/`###` 全部落到 Heading 2。
- 正文：`first_line_indent=22.4pt`、widowControl，但**未设两端对齐**（L184）。
- 配图：居中 + caption 8pt `#8198AA`（L191–192、L826–833）。
- 来源：末尾 "参考来源"（Heading 2）+ 编号超链接列表（L194–212）。
- 页脚：居中 "数治攻关 · YYYY-MM-DD"，8pt `#8CA1B1`（L214–218）。

**PDF（`_build_pdf_reportlab` L273–395）** 用 STSong-Light；标题先用 `_pdf_heiti_title_image` 按位图题字（L399–470）。**回退**：`_build_docx_fallback`（L481–570）与 `_build_pdf_fallback`（L573–753）。

## 2. 与《数治周报》的差距

《数治周报》全文**不用 pStyle**，全为直接格式化，所以只能比对原始 `rPr/pPr` 值（sz 单位=半磅）：

| # | 维度 | 当前导出 | 数治周报（期望） | 差距 | 改哪个函数/哪几行 |
|---|------|---------|------------------|------|------------------|
| 1 | 标题层级 | 单一 Title(24.5pt 黑体)+deck | 封面图→主标题(Noto Sans CJK SC, sz46=23pt, `#172033`)+副题(宋体 sz24=12pt `#0B57B7` bold)+眉行(宋体 sz19=9.5pt `#6B7280`) | 缺副题/眉行多级结构 | `build_docx` L146–166；PDF `title_style` L303 |
| 2 | 小标题层级 | `##`/`###` 统一折成 Heading 2 | 编号节题 `01 #{16pt}`+蓝底边框、`本周导读`(14.5pt)、`本周数治观察`(15.5pt) | 3 级定义全塌成 2 级 | `build_docx` L171–173；“01”前缀 L169–179 |
| 3 | 字体 | 正文宋体/标题黑体；正文字色 `#1C1C1C` | 正文宋体、标题黑体/Noto Sans；正文色 `#172033`(深蓝灰) | 正文色偏纯黑 | `build_docx` L133；`body_style` L306 |
| 4 | 字号 | 正文 11pt、H2 15.5pt | 正文 10.5pt、导语 11pt、节题 15.5–16pt、来源 9pt | 基本接近，正文略偏大 | `build_docx` L132；`caption_style`/`source_style` |
| 5 | 行距 | 1.68 倍（line=403 auto） | 正文 ≈1.48（line=355）、导语 1.5（line=360） | 行距偏松 | `build_docx` L135；`body_style` leading L306 |
| 6 | 两端对齐/缩进 | `first_line_indent=22.4pt`，**左对齐** | `jc=both` 两端对齐 + firstLine=424/448 | 缺 justify，边缘难看 | `build_docx` L184（加 `JUSTIFY`）、L181–186 |
| 7 | 配图说明 | 8pt `#8198AA` 居中，`{desc} · 来源：{src}` | 8pt `#6B7280` 居中，`图片来源：{desc}（{src}）` | 无"图片来源："前缀、色调不符 | `_caption_for`(content_blocks.py L235–244)；`build_docx` L832–833 |
| 8 | 来源/资料标注 | 文末一个 "参考来源" 列表 | 每条资讯尾部 `资料来源：…`(sz17=8.5pt `#6B7280`)+ 顶部媒体行 | 缺按节资料来源 | `build_docx` L194–212；`source_style` L308 |
| 9 | 栏目/导读框 | 无（仅 deck 底边框） | `本周导读`(sz29 蓝+底边框)、编号栏目、`数治观察｜` 引导(sz21 `#0B57B7` bold) | 缺节题框/callout | 新增 block 类型或 `build_docx` L169–179 |
| 10 | 页眉页脚 | 居中 "数治攻关 · 日期" 8pt | 底部横幅 `— 数治攻关 · 聚焦数据要素治理与价值释放 —`(18pt `#0B57B7`) | 文案/样式偏离 | `build_docx` L214–218 |

**结论**：本质差距集中在「多级标题结构、两端对齐（justify）、字号/行距微调、配图说明前缀与色、按节资料来源、栏目/导读框」六点。字号与字体已大体对齐，主要靠**对齐/行距/配色**拉近视觉。

## 3. 逐条"当前→期望→修改点"

1. **标题多级化**：当前 24.5pt 黑体单标题+10.5pt 灰摘要。期望 主标题(23pt `#172033`)+副题(12pt `#0B57B7` bold)+眉行(9.5pt `#6B7280`)。→ `build_docx` 标题块（L146–166）拆分 deck 为「副题+眉行」，并保留封面图置顶。
2. **小标题保留三级**：期望 `#`→H1、`##`→H2、`###`→H3。→ `build_docx` L173 改为 `level==1→"Heading 1" else f"Heading {level}"`（上限 3）。
3. **正文改两端对齐+微调行距**：加 `WD_ALIGN_PARAGRAPH.JUSTIFY`（L184），`line_spacing` 1.68→1.5（L135），`first_line_indent` 22.4→21.2–22.4 保持。
4. **配图说明**：`_caption_for` 改为 `图片来源：{desc}`（来源并入），`build_docx`/`_pdf_image_flowables` caption 色 `#8198AA`→`#6B7280`。
5. **按节资料来源**：为每个含来源的节生成 `资料来源：…`（sz17 `#6B7280`），替换/补充文末单一列表。
6. **栏目/导读**：给节标题加 `01 ` 蓝色编号+底线，正文首段可渲染 `数治观察｜`（`#0B57B7` bold 引导）。

## 4. Bug / 隐患

- **`_build_docx_fallback` 图片变形**：`_docx_picture_xml`（L477–478）硬编码 `cx=6000000 cy=3375000`（固定 6.54×3.69in EMU），**不按原图宽高比**，回退产物所有配图被拉伸。→ 应像 `_docx_add_image`（L798–808）用真实像素算 EMU。
- **跨引擎字体不一致**：`_pdf_heiti_title_image`（L399–470）找不到 simhei/msyh TTF 时回退 STSong（宋体）文本，与 docx 的 SimHei 命名不同，PDF 主标题可能与 Word 不一致。
- **回退路径硬失败**：`_build_pdf_fallback`（L589–590）无可用中文字体直接 `raise ExportError`，冷启动即崩。
- **XML 转义不健全**：`_xml_escape`（L473）用 `escape(quote=False)`，不处理控制字符（如 `\x0b`）；正文含非法控制字符时 document.xml 会损坏，docx 无法打开。
- **图片静默丢弃**：`_docx_add_image`/`_pdf_image_flowables` 图片字节为 SVG 或无法用 Pillow 解码时走 `except: return`，**静默少图**，前端无告警。
- **字号取整偏差**：`Pt(11.2)`→`w:sz 22`（实际 11pt）、`Pt(15.8)`→31（15.5pt），与声明值有 0.2–0.3pt 漂移；如要精确需用整数半磅值。
- **Caption 样式名与源色**：docx Caption 样式默认 `#4F81BD`，依赖 run 级覆盖，若某路径漏覆盖会跑出 Office 蓝，建议统一到样式级。
