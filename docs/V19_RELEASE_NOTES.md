# 数据要素治理 V19.0

## 检索理解
- “关键词”之外新增并强化“附加描述”，后端先理解用户的地区、时间、来源偏好、排除项和检索方式，再生成检索计划。
- 搜索规划模型只能扩展语义，不能覆盖用户原始关键词；所有新闻/政策/论文查询句必须保留原始主题。
- 检索结果先做用户意图门禁，再做来源验证和排序；provider relevance 只作为弱信号。
- 对“数据”这类超宽关键词增加领域锚点，普通材料/消费品/无关行业不能因为出现一个“数据”字就通过。
- 论文检索拆成国内学术来源与国际学术来源两路并行，降低单一数据库偏置。
- 首页推荐拆成国内新闻、国内政策、国际新闻、国际治理、中文论文、国际论文六路并行，并统一经过真实性和主题关联门禁。

## 写作理解
- 复杂“写作切口”先通过低成本非思考模式的需求分析器提炼成编辑简报；当用户同时开启自动佐证时，需求理解与资料检索并行，减少额外等待。
- 编辑简报包含目标、必须落实、明确避免、读者需求、立场和结构策略，并展示在“生成分析”中，但绝不会进入正文。
- 修复自动佐证路径中未定义 intent 的后端错误，避免“无引用 + 自动佐证”场景直接 500。

## 速度与成本
- 需求理解仅在用户提供较长附加描述/写作切口时触发，并缓存 20~30 分钟。
- 论文两路检索并行，新闻/政策仍并行；用户不会顺序等待多个来源。
- 写作阶段继续采用一次主生成 + 本地质量门禁 + 必要时一次定向修复。
