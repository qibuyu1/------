# V28.0 二次自查与稳定性优化

这轮不是新增功能，而是对 V27 做一次“边界条件优先”的代码审计。原则：**不增加 Tavily / Serper / DeepSeek 正常调用预算，不降低已经通过的检索、写作、导出和配图能力。**

## 修复

1. **来源页取图提前退出**：存在 `sourceHintUrl` 时，即使没有 Serper Key、Tavily 也没直接给 `sourceImages`，仍会读取来源页 OpenGraph / JSON-LD / 正文图。
2. **6—8 张图片时后排位置饿死**：全局探测上限保持 32/36 不变，但候选 URL 改为按图片位 round-robin 分配，保证每个位置都拿到探测机会。
3. **现代新闻页图片识别不足**：加入 `srcset`、`data-srcset`、`data-original-src`、`<picture><source>`，结合 article/main/figure 和尺寸提示排序。
4. **同域不同文章误认源图**：Serper 候选只有在同一页面 URL，或同域且来源标题强匹配时，才享受“精确来源”豁免。
5. **AI 短词误匹配**：英文短概念使用 token 边界，避免 `AI` 在 `detail/main/retail` 中误命中。
6. **模型图片位被静默截断**：`imageSlots` 从最多 5 提升到 8，`imageQueries` 从 6 提升到 9；不会增加模型调用，只保留已经返回的结构。
7. **中文日期识别**：支持“2天前、3小时前、2周前、2026年8月1日”等常见 Serper 中文日期。
8. **主题词单字误判**：不再用“中/上/在”等单字直接切概念；`数据中台` 保留为完整概念，`数据中心液冷技术` 不再被误判为关系型主题。
9. **结果 ID 不稳定**：Python 进程随机 hash 改为 BLAKE2s 稳定摘要。
10. **自查脚本不可直接运行**：`python scripts/quality_benchmark.py` 现在在干净项目目录可直接执行。
11. **来源图统计遗漏**：`source-meta` 现在计入真实图片统计，前端也明确标识为来源页图片。
12. **图片位规划去重错误**：旧 `_spread_indexes()` 在 4 个候选段落、要求 3 张图时可能只返回 2 个不同索引；V28 改为整数分位，准确保留可放置的目标数量。
13. **自动图片容易堆在小标题下**：模型明确指定“标题后”的图片仍尊重模型；系统自动补位图片则优先按选中的正文段落落点，避免同一节多图挤在开头。
