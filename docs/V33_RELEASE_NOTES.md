# V33 Release Notes：生成稳定性、材料优先、视觉完整度与历史工作流整改

V33 针对真实使用中仍存在的“推文偶发生成失败、代码解释图中文方块/信息不完整、上传材料权重不够、首页重复消耗 Tavily、第二次生成残留上一稿、公众号小标题与图片数量耦合”等问题做一次专项重构。目标不是增加更多功能，而是让现有功能在组合运行时更稳定、更快、更像真正的公众号编辑流程。

## 1. 推文生成失败：从接口、模型输出和前端状态三层同时修

- 首稿和改稿继续使用后台任务，不恢复长连接等待模型。
- DeepSeek 结构化写作改为**最多两次逻辑请求**：第一请求优先拿严格 JSON；如果返回的是完整 Markdown 文章则直接复用；只有空 JSON、无效 JSON 或截断时才进行一次纯 Markdown salvage，避免过去多轮重试放大超时概率。
- V4 写作/规划默认关闭 thinking，只有明确深度模式才开启，减少不必要的等待和推理 Token。
- 前端新一轮生成会递增 `generationEpoch`、清空旧 article id/预览；上一轮迟到的任务结果不能再覆盖当前主题。
- 未完成任务保存在 sessionStorage，刷新页面后继续轮询；502/503/504 和短暂网络错误不会立即判定整次生成失败。
- 后台任务池扩到 4 workers；运行中任务不会被 TTL/容量清理误删。

## 2. 代码视觉：不再允许“中文方块”和信息残缺

截图中的方块字根因是部署环境没有可用 CJK 字体，Pillow 回退到不支持中文的默认字体。V33 做双重处理：

- Docker 默认安装 `fonts-noto-cjk`；Linux 安装脚本也会检测并提示/安装 CJK 字体。
- 如果运行环境仍没有真正可用的中文字体，代码视觉会**直接禁用并回退到真实图片路线/留空**，绝不再输出一张满是方块的“成功图片”。
- DeepSeek 不执行任意 Python。文章完成后才用一次受限视觉规划器输出 DSL；本地 Renderer 负责像素执行。
- 视觉规划现在读取完整相邻段落上下文，而不是只看一句短锚点；新增 `relation` 关系图，并支持显式 `edges`。
- flow / causal / compare / relation 等结构图要求覆盖正文中的真实主体、动作和关系；没有真实数字时仍禁止 KPI 凭空造数。
- 图片数量只决定“放多少张图”，**不决定文章分几个小标题**。

## 3. 上传材料成为第一证据层

- 写作来源排序改为：**上传材料 > 用户手动选择来源 > 自动网络资料**。
- 上传 PDF/DOCX 在首稿 Prompt 中获得更大的正文预算；自动网络来源只负责补充和核验。
- 后续改稿继续保留上传材料更多原文，不再只保留开头一小段。
- 来源编号、事实提示和正文证据包都使用同一优先顺序，避免“明明上传了材料，最后文章却主要跟着搜索结果写”。

## 4. 首页 Tavily：一次结果缓存 7 天

首页滚动资讯改为双层 7 天缓存：

- 浏览器 `localStorage`：7 天内打开首页不请求后端 feed。
- 服务端磁盘缓存：`data/home_feed_cache.json` 默认保留 7 天，跨服务重启复用。
- 缓存过期后才刷新 Tavily；刷新失败时仍可返回旧缓存，而不是每次打开都重新消耗检索额度。

## 5. 第二篇推文与历史记录

- 生成页新增 **“生成其他推文”**：清空当前文章、旧自动证据、旧任务状态和旧预览，但保留用户上传/手动证据，方便继续写下一篇。
- 顶部新增 **“历史记录”**，服务端使用 `HistoryStore` 持久化最近文章（默认 30 天、最多 80 条），可查看并恢复过去生成稿。
- 每次新生成都有独立 generation epoch；直接改关键词后也不会再显示上一份文章结果。

## 6. 取消“智能小节”，公众号小标题成为正文基本结构

- 前端移除“智能小节/智能节点”开关。
- 公众号稿默认必须有自然、有信息量的小标题；目标数量只由篇幅和论证复杂度决定：短篇约 3—4，中篇 4—6，长篇 5—7，更长内容 6—8。
- 图片位置由段落信息密度和视觉适配度单独选择。用户要 3 张图但正文需要 6 个小标题时，仍然保留 6 个小标题，只在其中 3 个合适位置放图。
- 继续禁止“问题 / 机制 / 影响 / 判断”等机械栏目式标题，避免重新变成 AI 六段论。

## 7. 速度与成本

- 前端不再在生成前先做一次阻塞式自动搜证据；需要自动补证据时由后端统一负责，避免重复搜索。
- 自动证据首轮已经得到 3 条可用高质量来源时不再强制进行第二轮放宽搜索；只有资料确实过薄才扩展一次。
- DeepSeek 常规生成走单请求成功路径；视觉规划发生在文章完成后，不阻塞正文交付。
- 首页 7 天缓存直接减少 Tavily 消耗。

## 8. V33 最终质量基准

- 单元 / 回归 / 服务测试：`154 passed`。
- 检索正负样本最小区分 margin：`86`。
- Tavily 主检索固定样例：`5` 次；Serper 搜索兜底最多 `3` 次。
- 无来源正文图片首轮 Serper Images：`1` 次；有来源页原图：`0` 次。
- 结构型智能视觉可直接走代码图：Serper Images `0` 次。
- 首稿 Prompt 代理：`8,796` 字符，且不包含视觉 DSL 字段。
- 实际导出含代码封面、关系图和中文正文的 DOCX/PDF，并逐页渲染检查；中文、图片、段落、分页均正常。
