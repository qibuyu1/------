# V26.0 质量强化版发布说明

V26 的目标不是增加更多按钮，而是在 V25 已经能完成完整工作流的基础上，把 **检索、写作、配图与导出** 同时向“更准、更自然、更稳定、更省调用”推进，并设置离线质量基准，避免后续优化一处、退化另一处。

## 1. 检索：理解“关系型主题”，不是只做字符串包含

### 1.1 概念 OR 组与关系型门禁

对于“数据在技术突破上的作用”“数据资产入表对企业融资有什么作用”“可信数据空间如何促进产业协同”这类自然语言主题，系统先识别两侧或多侧概念，再用少量常见中文表达建立 OR 组。例如：

- 数据 → 数据要素 / 数据驱动 / 数据赋能 / 数据分析；
- 技术突破 → 关键核心技术突破 / 技术创新 / 科技创新 / 技术攻关；
- 数据资产入表 → 数据资源入表 / 数据资产化；
- 融资 → 质押融资 / 授信 / 增信 / 融资担保；
- 可信数据空间 → 数据空间 / 数据基础设施；
- 训练数据 → 数据集 / 语料 / 数据供应链 / 数据标注；
- 数据质量 → 数据质量治理 / 质量评估 / 数据清洗；
- 数据跨境 → 数据出境 / 跨境数据流动 / 数据出境安全评估。

关系型查询要求结果至少覆盖两个语义侧，避免“数据中心液冷技术突破”因为同时出现“数据”和“技术突破”就被误判为“数据推动技术突破”。

### 1.2 搜索词更像人实际在浏览器里输入的词

长问句只保留为辅助通道，主 Query 优先使用 2—4 个高信息量词。例如：

- `数据在技术突破上的作用` → `数据 技术突破` / `数据要素 关键核心技术突破` / `数据驱动 技术创新 研发`；
- `数据资产入表对企业融资有什么作用` → 主 Query 直接保留 `数据资产入表`，而不是降级成宽泛的“数据资产”。

简单附加描述不再额外调用一次检索意图 LLM；只有真正包含多个约束、排除项、来源偏好或对比要求时才使用低成本意图规划器。

### 1.3 主检索不增调用，Serper 兜底减半

固定“新闻 + 普通网页 + 国际补充 + 政策 + 论文”样例中，V25 与 V26 的 Tavily 主检索均为 5 次；V26 没有为了语义扩展额外增加主检索请求。


V25 的浏览器式兜底会对最多 3 个 Query 分别调用 Web + News，最坏 6 次。V26 变成：

- 最多 2 个互补 Web Query；
- 只有主 Query 再跑 1 次 News；
- 一轮最多 3 次；
- 原文核验后仍偏少时，不重复相同 Query，只允许 1 条尚未使用的 Web 变体；
- 政策 `site:gov.cn` 补充仍只在确实缺政策时条件触发。

这样扩大普通网页、政策解读、研究文章的召回面，但不靠重复搜索堆结果。

## 2. 写作：默认不是模板，而是编辑自由

### 2.1 减少“AI 六段论”

默认结构明确要求先确定中心判断，再根据证据之间的因果、转折、递进关系决定是否需要小标题。普通文章允许 0—3 个自然小标题，内容连续时可以完全不用标题。

本地质量门禁会识别：

- `问题：/做法：/机制：/影响：/条件：/判断：` 等抽象栏目式小标题；
- 4 个以上过于整齐的默认章节；
- `一文读懂 / 深度解析 / 全景观察 / 全面解读 / 新范式 / 正在重塑` 等常见 AI/营销标题公式；
- `这意味着 / 更重要的是 / 换句话说 / 值得注意的是` 等连接词高频重复；
- 大量短碎段、JSON/Prompt 字段泄漏、标题前缀污染。

只有草稿实际触发质量问题时，才追加一次定向主编修复；正常草稿保持单次生成，避免为了“质量”无条件增加 Token。

### 2.2 证据包更短但信息更完整

写作前不再把每条来源的长正文直接塞进 Prompt。V26 在本地先去掉导航、广告、责任编辑、上下篇、扫码等噪声，再按主题与来源标题挑选完整高信号句子，并恢复原始顺序。

首稿每条来源证据上限从 V25 的约 3200 字符降到约 1700 字符；主编、长度修复与再次修改阶段也同步缩短来源摘要。离线同一份 6 来源长材料测试中，首稿 Prompt 字符代理从 **24,298** 降到 **13,318**，减少约 **45%**。

### 2.3 写作简报不再浪费一次模型调用

简单的一句话写作角度直接交给主写作模型；只有包含多个明确控制项的写作简报才额外调用一次小规划器，并且与自动证据检索并行。

## 3. 配图：源新闻先行，减少搜索，同时提高拒错能力

### 3.1 来源页图片拥有“第一拒绝权”

正文写到具体新闻、政策、案例或机构活动时，如果该来源在正文 Extract 阶段已经返回真实图片：

1. 先在来源页图片池中做语义、URL、尺寸与可下载性检查；
2. 有合格原图时 **不调用 Serper Images**；
3. 全部不合格时才执行 1 条精确的原文标题/章节回退 Query。

没有来源页图片时，也从 V25 的两条并行图片 Query 改为先跑 1 条高信息量 Query，失败后再跑 1 条真正不同的回退 Query。

离线调用预算对比：

- 无源图：V25 初始 2 次 → V26 初始 1 次；
- 有源图：V25 初始 1 次 → V26 初始 0 次。

### 3.2 修复来源页“后排装饰图”误入正文

V26 自查发现 V25/V26 早期实现虽然给来源页图片保存了位置，但图片去重阶段曾丢失 `position`，导致“第 7 张以后降权/拒绝”的保护实际没有生效。本版已修复：

- 去重后继续保留来源图片位置；
- URL 包含 logo / banner / avatar / qrcode / icon / advert 等直接过滤；
- 来源页第 7 张及以后不再仅凭“同一来源页面”通过语义门禁；
- 找不到合格图宁可留空，再走一次精确回退，不用相关卡片或页尾装饰图凑数。

### 3.3 图片说明更像编辑成品

系统生成封面不再在封面下重复打印一次标题型图片说明；正文图片说明会压缩到合理长度，只保留必要解释与来源，Word/PDF/HTML 使用同一内容块。

## 4. Word / PDF：使用同一套版式来源

V25 的 Word 与 PDF 仍可能因为两个排版引擎而出现字号、分页和图片尺寸差异。V26 改为：

- DOCX 作为主要版式源；
- 运行环境存在 LibreOffice/soffice 时，PDF 直接由最终 DOCX 无界面转换；
- 因此 PDF 与 Word 的字体层级、页边距、分页、图片位置尽量一致；
- 没有 LibreOffice 时仍保留经过优化的 ReportLab PDF 兜底。

中文长文排版重新校准：

- A4 页面；
- 黑体类标题、宋体类正文；
- 正文约 11.2pt，首行约 2 字符缩进，舒适行距；
- 标题开启 keep-with-next / widow control，减少“标题孤零零留在上一页”；
- 封面与正文图片同时限制最大宽度与最大高度，避免纵向长图挤乱页面；
- 图片说明与图片尽量保持在一起。

本版已实际生成 DOCX/PDF 并逐页渲染检查；LibreOffice 主路径下两种格式视觉层级保持一致。

## 5. 离线质量基准与回归保护

新增 `scripts/quality_benchmark.py`。它不访问外网、不使用真实 Tavily / Serper / DeepSeek Key，通过 Mock 固定检查：

- 语义正例与假阳性的分离度；
- Serper 兜底调用预算；
- 图片搜索初始调用预算；
- 来源页图片零搜索路径；
- 写作 Prompt 体积代理。

详细前后对比见 `docs/V26_QUALITY_BENCHMARK.md`。

## 6. 兼容性原则

V26 保留 V25 已经工作的能力，不改变用户工作流：

- 新闻 / 政策 / 论文查询；
- 国内优先与来源核验；
- 上传文件和引用资料；
- 自动补充证据；
- 生成、局部修改、整篇重写、撤回/恢复；
- 封面 + 正文配图；
- 配图与来源审计；
- HTML / Markdown / Word / PDF 导出；
- 生成页左右栏等高布局。

没有真实 API Key 的环境下，本版没有伪造“线上命中率”或付费 API 实测数据；线上结果数量仍取决于部署时的 Key、额度、网络和上游索引。
