# V30 Release Notes：智能混合配图 + 本地代码视觉引擎

V30 在 V29 的真实图片匹配和二维码/垃圾图门禁之上，新增一条**完全本地、受控的代码视觉链路**。目标不是用示意图替代新闻原图，而是让不同内容走最适合的视觉路线：具体事件尽量真实，机制与数理分析优先解释，真实图不可靠时再用代码图兜底。

## 1. 五种配图策略

生成页新增“配图策略”：

- **智能混合（默认）**：具体案例、新闻、政策优先源图；流程、机制、因果、对比、分层、时间线、指标等结构化内容可以直接画；真实图找不到或不够相关时自动代码绘图兜底。
- **真实图片优先**：先查来源页和 Serper；最终仍没有可靠图时再画，尽量保留现实感。
- **解释图优先**：结构化段落更积极地直接绘制，具体案例仍保留真实来源优先。
- **全部代码绘图**：正文不调用 Serper Images，所有正文视觉都由本地 Renderer 生成；适合不想配置图片 API、希望视觉统一的部署。
- **仅真实图片**：保持 V29 的“宁缺毋滥”；找不到可靠真实图时留空，不用代码图补位。

封面始终由本地代码视觉引擎生成，不占正文图片数量。

## 2. 代码视觉不是固定模板

新增 `app/code_visuals.py`。它不执行模型生成的 Python，也不调用任何图片生成 API。DeepSeek 只在原本的文章 JSON 中顺带给出很小的视觉意图（`visualIntent / visualType / visualPlan`），真正绘图由受信任的本地 Renderer 完成。

当前正文视觉类型：

- flow：流程 / 生命周期 / 价值链路
- causal：原因 / 风险 / 机制
- compare：前后对比 / 传统 vs 新方式
- layered：分层架构 / 能力体系
- network：多主体协同 / 数据空间 / 生态
- timeline：政策或项目演进
- kpi：真实数字卡片（无真实数字时不会编造数字）
- matrix：价值 / 风险等二维判断
- concept：不适合真实照片、又不应硬套流程图的编辑型解释视觉

封面会根据文章内容在政策海报、网络结构、产业场景、几何抽象、编辑视觉、大数字等方向间自动选择，不再只有一个固定蓝色模板。

## 3. 找图与绘图的关系

V30 默认路由：

`文章图片位 -> 是否是具体新闻/案例 -> 来源页原图 -> Serper真实图 -> 语义/二维码/可用性门禁 -> 若仍失败则代码绘图`

对于明显的结构化分析：

`流程/因果/对比/分层/时间线/指标 -> 本地视觉适配分 -> 直接代码绘图（可跳过 Serper）`

因此提升配图完成度不依赖“多搜几次”。已有 V29 的来源页 OpenGraph/JSON-LD/srcset 抽图、二维码像素识别、Logo/关注卡过滤、业务场景语义门禁和图片下载探测全部保留。

## 4. 成本与速度

V30 没有新增 DeepSeek API 调用。视觉意图跟随原文章结构化响应返回；本地绘图只消耗 CPU。

离线质量守恒基准：

- Tavily 主链：5 次（不增加）
- Serper 搜索兜底：最多 3 次（不增加）
- 无来源真实图片的初始 Serper Images：最多 1 次
- 有可靠来源页图片：0 次初始 Serper Images
- 智能模式下显式结构图：0 次 Serper Images
- 全部代码绘图：0 次 Serper Images
- 真实图片优先且真实图失败：最多 2 条不同图片 Query 后本地绘图兜底
- 首稿 Prompt 字符代理：13,582，仍低于 16,000 质量预算

## 5. 适配与安全

- 输出统一为 1600×900 PNG data URI，可直接进入网页预览、DOCX 和 PDF 现有图片管线。
- 字体运行时自动发现 Linux / Windows / macOS 常见 CJK 字体；也可用 `DEG_VISUAL_FONT*` 环境变量指定字体路径。项目不会打包字体文件。
- 不 `exec` / `eval` DeepSeek 生成代码。模型只描述“画什么”，本地 Renderer 决定“怎么画”。
- 视觉 DSL 会经过长度、类型、节点数量和字段白名单清洗。
- KPI 图只有检测到真实数字证据才使用数字视觉；否则退回编辑型概念图，避免为了好看编造数据。
