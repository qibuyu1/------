# 排版参数回调对比（t9 收口 t5）

> 针对 t6 审查，对实验目录排版做收口。目标：可测排版参数更贴近《数治周报.docx》基准，同时保留"文章原生小标题层级、不照搬周报 01/02 编号与数治观察框"的设计取舍。未改原项目、未调外部 API。

## 1. 参数调整前后对比表

|---------|--------|--------|-----------------|
| 正文 字号 | 12pt（`w:sz 24`） | **11.5pt（`w:sz 23`）** | 10.5–11pt（`sz 21/22`） |

## 2. 取舍说明：12pt vs 11.5pt vs 11pt

- **选定 11.5pt / 1.5**。理由：
  1. 收口审查认为 t5 的 12pt（小四）+ 行距 1.6 偏大偏松，正文相应变长、版面偏空；周报正文是 10.5–11pt、行距≈1.5。
  2. 11pt 虽最贴周报基准，但本产品是"公众号式长文"，11pt CJK 在桌面/移动端阅读略紧；**11.5pt 介于五号(10.5)与小四(12)之间**，明显比 12pt 靠近基准，又保住可读性。
  3. 行距取 **1.5**（与周报 1.48–1.5 一致），既满足"≥1.5"要求，也压缩了垂直空档。
  4. 若 review 判定"必须严格贴基准"，把 `normal.font.size` 与 ReportLab `fontSize` 从 11.5 改回 11、首行缩进从 23 改 22 是一行改动（无需重构）。

## 3. 说明收敛 + 去重

原先 `_caption_for`(content_blocks)、`_figure_caption`(exporter)、`_visual_caption`(pipeline) 三处各有一套"图片来源：{desc}（来源：{src}）"拼接逻辑，存在漂移风险。已**统一为一条可复用路径**：

- 新增 `content_blocks.compose_figure_caption(description, source, *, caption="", provider="")` 作为唯一官方实现（处理 generated-cover 返回空、已有 caption 直出、否则按描述+来源合成）。
- `_caption_for`、`_figure_caption`、`_visual_caption` 三者都**委托调用**该函数，仅各自负责提取字段。
- 消除了三处重复；预览 / DOCX / PDF 三条链路的说明格式完全一致、不会再各自漂移。

## 4. 来源段落说明（按节资料来源）

- 全局"资料来源"块（8.5pt 灰 `#6B7280` + 11pt 灰标题）已到位并符合收口要求。
- **按节资料来源未实现**（取舍说明）：文章数据模型里 `article["sourceList"]` 是**全局列表**，不含"该来源属于哪一节"的归属信息；实现"在正文各节末尾呈现该节来源"需对来源做启发式分词/标题匹配来分类，属高风险低收益（易错配、且可能引入与周报编号类似的"栏目化"观感）。故保留**文章末尾的全局资料来源块**，满足"来源信息简洁含蓄、不破坏正文"的目标。
